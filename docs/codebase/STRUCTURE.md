# Structure — what is where, and what you can ignore

The repository has two halves that are easy to confuse. One is **read** by an agent;
the other is **run** by it.

    AGENTS.md            the entry prompt for any coding agent
    SKILL.md             the protocol itself: ground rules, journeys, the scored bar
    *.md at the root     one mode or module each — read only when you need that mode
    profiles/            per-application anchors: URLs, gates, journeys, known traps
    examples/            a worked case, including the demo page this repo tests itself with
    scripts/             the eleven executable programs        <- the code
    scripts/lib/         the two things more than one script needs
    test/                behaviour tests (node --test)
    promotion/           the product loop's own scorecard, journeys, log, and evidence
    docs/                this packet
    .tours/              CodeTour walkthroughs pointing into live source
    ci/qa-gate.yml       a drop-in CI job for consumers, not for this repo

## The code, in one table

| File | Needs a browser | What it answers |
|---|:---:|---|
| `scripts/lib/browser.mjs` | — | "where is a Playwright I can borrow, and how do I report an error without leaking the URL?" |
| `scripts/lib/ledger.mjs` | — | "what is the current state of every defect, and which lines could I not read?" |
| `scripts/qa-memory.mjs` | no | the append-only ledger: add a pass, add a finding, list what is open, list the permanent re-verify sweep |
| `scripts/qa-gate.mjs` | via children | the deterministic deploy verdict; spawns the three checks below |
| `scripts/live-signal.mjs` | for the rendered half | "is this actually live right now, and is the control I removed really gone?" |
| `scripts/head-check.mjs` | optional | "does this page declare a document shell, and does it hold at every width?" |
| `scripts/pixels.cjs` | yes | screenshots plus mojibake / console-error / overflow checks |
| `scripts/prettify-audit.mjs` | yes | visual-craft signals scored V1–V9; advisory, always exits 0 |
| `scripts/clutter-audit.mjs` | yes | a conservative inventory of what is on screen; advisory |
| `scripts/self-check.mjs` | optional | this repo's own proof: docs present, scripts parse, demo surface intact |
| `scripts/shell-regression-proof.mjs` | no | "does the gate actually go red?" — deletes the demo page's shell and demands a failure |

`pixels.cjs` is the only CommonJS file. Its path is a published command that other
repositories' QA profiles hard-code, so renaming it would break them; it reaches the
shared resolver with a dynamic `import()` instead.

## Which Markdown to read, and when

Reading all eighteen root documents front to back is the wrong way in. `SKILL.md` is
the protocol; the rest are modules you open when a pass sends you there:

| You are about to… | Read |
|---|---|
| remove, merge, or defer existing UI | `DECLUTTER.md` |
| add a capability, state, route, or layout | `REVAMP.md` |
| change only visual tokens | `PRETTIFY.md` |
| attack the app deliberately | `REDTEAM.md` |
| judge the agent *under* the UI, not the UI | `DEPTH.md` |
| wire the gate into CI | `GATING.md` |
| prepare a review packet or a proof clip | `HANDOFF.md`, `PROOF.md` |
| start a *new* app so it scores well on day one | `BAR-DEFAULTS.md` |

`PLATFORM.md` maps how those fit together; `REFERENCES.md` and `TASTE.md` are
background.

## What is not source

`promotion/` is the product loop's own record — a scorecard, an append-only defect
ledger, and committed evidence. It is dated history and is not rewritten. Two PNGs in
`promotion/evidence/` are regenerated by `scripts/head-check.mjs`; the rest are
receipts.
